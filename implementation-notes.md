# Implementation notes

## Piece 1: deterministic code

Parser, record schema, verifier and script check, with no model calls. Built on a branch of the Agent Research Library repo (last commit there `56c10d2`) and moved here with fresh history on 2026-11-24.

## Decisions
- `lib/sanitize.ts` is a copy of `src/sanitize.ts` from the Agent Research Library (a private repo) at `8f37865` (imports nothing).
- `FullRecord` is `.strict()` everywhere, so `why_it_matters_for_justin` is rejected, not silently stripped. Same for `compact`.
- Numbers match by token: `0.68` does not match inside `0.684`. A range such as `0.91–0.94` is matched whole in the quote.
- Dropping a quote cascades: its numbers and limits are dropped; an `authors` claim keeps its other ok quote ids and is dropped if none remain. `inference` claims always stay (with failed quote ids removed) and are counted.
- `Script` schema also requires a `result` and a `limits` beat, and forbids repeating any kind but `method` (the spec says 5 or 6 beats but not which kind a 5-beat script omits).
- `checkScript` lets the paper's own arXiv id appear on screen (credits); any other numeral must equal a numeral inside a verified number's value, so a range value allows both ends.
- Papers are fixtures only for the CC-BY 4.0 licenses; fixtures are listed in `test/fixtures/README.md`.

## Verifier hardening (second commit)
- Quotes need 6 words (paragraph, abstract) or 3 tokens (table) after normalization, else `too_short` (not ok, dropped).
- `numeral_issues`: numerals in free-text fields must equal a numeral of an ok number's value or appear in an ok quote; the verified record's arXiv id is exempt. No year carve-out: a year must come from a quote. Side effect: labels like "Table 2" or "H1" in free text are flagged unless quoted.
- `applyVerification` drops claims, limits, `compact.results` entries and numbers carrying an unverified numeral; single-string fields stay and are returned as `reported`.
- `FullRecord` superRefine: unique quote and number ids, no dangling quote references (malformed, not a verification failure).
- `checkScript` exempts the verified record's arXiv id, never the script's; a differing `script.paper.arxiv_id` is `paper_mismatch`. All `\p{Nd}` digits are folded to ASCII in `normalizeNumberText` (also `٫` as a decimal point) and narration is tested with `\p{Nd}`.

## arXiv HTML quirks
- Abstract paragraphs are `<p class="ltx_p">` inside `div.ltx_abstract`, not `ltx_para`; ids come from the parser (`abstract.p1`).
- Body paragraphs are `div.ltx_para`; in lists they nest, so only the outermost is kept (the text of nested ones is inside it). Headings inside sections like `S1.SS0.SSS0.Px1` are `ltx_paragraph` sections, so `section_title` can be a run-in heading.
- 2611.26897 leaks LaTeX preamble junk (`\setmainfont` options) as top-level paragraphs `p1`, `p2` outside any section. They are skipped (no section).
- Math alttext is raw LaTeX (`\times`), so prose like `condition×task` parses as `condition\timestask`. Numbers in math are preserved.
- Tables are `figure.ltx_table`; cells joined with ` | `. Appendices are kept; the bibliography is removed.
- `https://arxiv.org/html/2611.26966v1` returned 404 (a CC-BY candidate); replaced by 2611.26897.

## Not done
- No affiliations from the parser (the gold record has them by hand). No PDF fallback. Equation-heavy text is only as readable as the alttext.

## Verifier: whole-record scan and one tokenizer (2026-11-24, after an automated security review)
- The numeral scan walks every string field of the record (`stringFields`), so a field added to the schema later is scanned by default. The skipped fields are listed in `EXEMPT_FIELDS`: ids, quote text and number values (each verified on its own), and machine fields (`paper.arxiv_id`, `version`, `url`, `license`, `read_at`, `source`, `compact.license`, `code_url`, `depth`). Piece 3's workflow must set those machine fields itself from arXiv metadata and the fetch, never from model output, because their content is not scanned.
- Paper metadata (`paper.title`, authors, affiliations, `quotes[].section_title`, `figures[].caption`, `named_people`, `compact.results[].location`) may also use numerals from the parsed page's title, authors, headings, captions and anchor ids, so "Table 7" or "S8.T7" passes there but not in prose.
- Entries of `likely_overclaims`, `named_people`, `figures` and `compact.applies_to` with an unverified numeral are dropped like claims; `compact.method` joins the single-string fields that are reported for regeneration.
- `numerals()` no longer strips leftover commas: `normalizeNumberText` already removed valid thousands separators, so "1,2" is two numbers, not 12. `containsNumber` requires every numeral of a value to be a whole numeral token of its quote and checks for a glued digit on both sides whatever the value starts or ends with, so ".5" no longer matches inside "10.5".

## Piece 3 library (2026-11-26)

Built `lib/arxiv-feed.ts` (`parseArxivRss`, `selectNew`, `validatePick`) and `lib/reader.ts` (`ReaderOutput`, `paperForReader`, `assembleRecord`, `repairMessage`, `licenseFromAbsHtml`), with tests and two fixtures (`test/fixtures/rss-sample.xml`, `test/fixtures/abs-2611.27106.html`).
- **Feed format.** The live cs.AI+cs.CL feed held about 500 items (1 MB) with all four announce types (new, cross, replace, replace-cross), so the sample is six unedited items. `<category>` repeats per item; `<arxiv:announce_type>` is a real element (cheerio xmlMode needs the selector `arxiv\:announce_type`). The description is "arXiv:<id>v<n> Announce Type: <type> \nAbstract: <text>", and the version is `v2` or higher on replacements. Abstracts contain raw LaTeX (`$P_\theta$`), kept as is.
- **Abs page.** The license is `<div class="abs-license"><a href="http://creativecommons.org/licenses/by/4.0/" class="has_license">`, an http URL; `licenseFromAbsHtml` upgrades it to https. Papers with no license link have no `has_license` anchor, so the function returns null whenever the block or href is missing.
- **ReaderOutput** omits `quotes[].section_title` as well as the fields the brief named; `assembleRecord` fills it from the parsed page (abstract blocks "Abstract", body paragraphs their section title, tables and figures ""). It spreads the model output into `FullRecord.parse`, so an unknown field (such as `why_it_matters_for_justin`) is rejected by the strict schema rather than silently dropped. `ReaderOutput.parse` itself strips unknown keys, so callers should pass the model's raw object to `assembleRecord` only after `ReaderOutput.parse` if they want stripping, or the raw object if they want rejection.

## Piece 4 library (2026-11-26)

- `lib/number-words.ts`: `spokenNumbers(text)` returns digit numerals (via `numerals()`) plus English number words as normalized numeral strings. Whole-word matching, "a hundred/a thousand", "and" inside a number, "point" decimals. A bare "hundred" or "thousand" with no count is not a number; ordinals and fractions are ignored. "one" counts as 1 ("no one" yields "1"), which is harmless because 0 to 10 are always allowed.
- `lib/script-schema.ts`: `BEAT_KINDS` and the plain-zod `ScriptOutput` the scriptwriter fills. `lib/script.ts` imports and re-exports `BEAT_KINDS`.
- `lib/script.ts`: new issue code `unverified_spoken_number` (a spoken number must be a verified value or a whole number 0 to 10); `assembleScript(out, record)` fills `paper` from the record and runs `Script.parse`, which throws on bad order or counts.
- `lib/verify.ts`: `stripReported(record, reported)` removes sentences holding a reported numeral from the single-string fields `applyVerification` only reports. It works on any reported path, not only the four named fields; nullable fields (`change_for_agents`, `compact.limits`) become null, everything else "". Sentence split is on `.!?` followed by whitespace, so an abbreviation such as "et al. 2024" splits there; the cost is a slightly over-eager strip, never a surviving numeral.
- Surprise: the spoken-number check also catches numbers the narrator says that are not in digits anywhere, so the gold script needed no change but a model that writes "twenty twenty-six" will be flagged unless that year is a verified value.

## Piece 4 hardening (2026-11-26)

An adversarial review showed a script could state numbers the record never verified: misspelled words ("fourty-two" read as 2), digit by digit ("nine five percent"), zero-width or U+2011 characters inside words, a dropped scale ("one point two billion" read as 1.2), fractions and multipliers ("a fifth", "double"), and number words in `on_screen`, which was never checked. Patching the word parser case by case would not hold, so the scriptwriter no longer writes numbers.

**Placeholders.** In `narration` and `on_screen` the scriptwriter writes `{{id}}`, where `id` is a `numbers[].id` of the verified record. `ScriptOutput` beats are `{ kind, narration, on_screen }` (templates, no `number_ids`). `assembleScript` renders them: a placeholder must name a number of the record (else it throws), narration gets `spokenValue` (throws when null), `on_screen` gets `screenValue`, and `number_ids` is the ids used, narration first, in order, deduped. The stored `Script` beat is `{ kind, narration, on_screen, narration_template, on_screen_template, number_ids }`, strict.
- `lib/number-render.ts`: `spokenValue` handles integers up to 999 billion (thousands separators fine), decimals digit by digit ("0.50" is "zero point five zero", nothing rounds), `%` ("percent"), `x`/`×` ("times"), suffixes `K`/`k`, `M`, `B`/`bn` (only on a number below one thousand), a leading minus, and one range `a-b` ("a to b"; the en dash in "0.91–0.94" is folded first, the gold record has one). Everything else returns null: `~5`, `<5`, units, leading zeros, `.5`, lowercase `m`/`b`, 13 digits or more. A null number can be shown on screen but not spoken. `scaledNumerals` gives the scaled form of a K/M/B value ("1.2B" gives 1200000000).
- `spokenNumbers` now drops format characters (zero-width, soft hyphen), folds every dash, and applies a scale word after a decimal ("one point two billion" gives 1200000000). Without this the belt check could not tell "1.2" from "1.2 billion".
- The stored script carries its templates so `checkScript` can re-render from the record: `narration` and `on_screen` must equal the render and `number_ids` must equal the placeholders used (`render_mismatch`). This is what lets `publish_night` recheck a stored `script.json`; editing the rendered text after assembly fails.

**Template rules** (`lib/script-template.ts`; issue `number_outside_placeholder` for numbers, `unverified_name`, `link_in_text`). Placeholders are removed from the raw text first (so a fullwidth `｛｛n1｝｝` is not mistaken for one), then NFKC.
1. Character whitelist: Latin letters in Basic Latin, Latin-1, Latin Extended-A/B (to U+024F) and the precomposed Vietnamese block, combining marks, the space, and `' ’ ‘ " “ ” , . ; : ! ? ( ) - – — / &`. No digit of any script (`\p{N}` after NFKC, which folds fullwidth, superscript, circled and vulgar-fraction forms). I tightened the brief's `\p{L}` to Latin script: CJK numerals (四十) are letters and Cyrillic and Greek letters look Latin ("twеnty" with a Cyrillic е), so any other script is rejected. IPA, phonetic extensions and Latin Extended-C/D are rejected as well: they hold small capitals ("ꜰɪᴠᴇ") that NFKC leaves alone. Look-alikes inside the allowed range (dotless i, ø, ł, đ, ð, ħ, ŧ, ß, æ, œ) are mapped to ASCII before number words are matched, so "nıne" and "twø" are caught while "Łukasz" and "Đặng" still pass. Zero-width characters, the soft hyphen and U+2011 (NFKC turns it into U+2010, which is not listed) are rejected here. Newlines and tabs are rejected too.
2. Words (lowercased, accents and marks removed, split at hyphens): exact number words (zero, two to nineteen, the tens, hundred to trillion, dozen, half/halves, quarter(s), third to tenth and their plurals as fractions, twelfth and twentieth to ninetieth, double/triple and forms, twice, thrice, percent, percentage, hundreds/thousands/millions, decades like "nineties", `-fold` compounds). "first" and "second" are allowed.
   - "one" is rejected unless preceded by no/any/every/some or followed by "of" or "another" ("no one", "one of the", "one another"). The brief named the first two; "another" is my addition because "one another" is common prose and carries no count.
   - "point" is rejected when next to a number word or a placeholder (it would build "{{a}} point {{b}}" into an unverified decimal). Next to a number word this is redundant, since the number word is already rejected.
   - Placeholder boundaries: only a space (or the text's end) may follow a placeholder, after at most a run of closing punctuation, and only a space (or the start) may come before it, after opening punctuation. So `{{n}}K`, `{{n}}x`, `{{n}}th`, `-{{n}}`, `{{a}}/{{b}}`, `{{a}}–{{b}}` and `{{a}}:{{b}}` fail. Two placeholders need a word between them (a bare `{{a}}, {{b}}` fails). These words are rejected next to a placeholder: k, m, b, bn, mn, mil, mm, x, fold, pct, pc, grand, th, st, nd, rd and "times" right after it, and minus, negative, plus right before it. "times" is my call: "{{n}} times faster" turns a count into a multiplier the record may not state, while "ran it many times" is fine; the scriptwriter can say "{{n}} runs".
   - Near misses: a token of four or more letters one edit (insert, delete, substitute, swap neighbors) from a number word of five or more letters is rejected: "fourty", "ninty", "fivty", "eigth".
   - Contained number words: "twentieth", "hundredth", "millionth", "fortytwo", "threefold" (substring of a number word of five or more letters, "eight" excepted because of height/weight/freight), and number words run together ("onetwo", via a segmentation check).
   - A number word split across tokens ("for ty", "thir teen", "t w o", "per cent") is rejected by joining up to five neighboring tokens.
   - Roman numerals in capitals ("XII", "MIX", a lone "V" or "X"); a lone "I" is the pronoun.
3. Allowlists, kept minimal and tested. `FUZZY_ALLOWLIST` (46 words) holds ordinary words one edit from a number word of five or more letters: even, seen, sever, tree, thee, there (a swap of "three"), threw, height, weight, light, might, night, right, sight, tight, fight, fort, forth, forte, foray, tent, teeth, nifty, filth, doable, doubly, doze, twine, tripe, trifle, calves, halve, quartet, percept and similar. Found by checking the number words against the system dictionary; without them the rule rejects "right", "light" and "there". A test checks every entry really is one edit away, so it cannot go stale. `SUBSTRING_ALLOWLIST` holds words that contain a number word ("quarterly", "headquarters", "millionaire", "percentile", "triplet", "doublet", "weighty"). Ordinary words that pass are tested ("often", "tension", "tenant", "stone", "someone", "point" in "the point is").
4. Short number words are not fuzzy-matched ("fuor", "fiev", "nien"): at three and four letters nearly every neighbor is an ordinary word (four: your, hour, pour; five: fine, fire, live), so the rule would reject normal prose.

**Names.** A run of two or more capitalized words (a letter that is `\p{Lu}` first; hyphens and apostrophes allowed inside; separated by a single space) must appear verbatim, case-sensitive and with no letter, digit or hyphen touching either end, in `paper.title`, an `authors_as_printed` entry, a verified `named_people` entry or a verified quote's text. A run that opens a sentence may drop its first word only when that word is a common opener (The, This, Then, ...): "The Terminal-Bench team" passes if "Terminal-Bench" is in the sources, "Sidney Pearson" does not pass because "Pearson" is an author. A single capitalized word right after "by", "from" or "with" must be a whole word of those sources ("work by Smith" fails, "by Shapiro" passes). Possessive "'s" is stripped. Affiliations are not a source (model-written and not verified against the page). `on_screen` should be in sentence case: a Title Case line is a run of capitalized words and fails.

**Links.** Not in the brief: a template with `://`, `www.` or a domain ending in a common top-level domain fails (`link_in_text`), because a model reading a hostile abstract could be talked into speaking or showing a URL. "arxiv.org" in a credits line therefore fails; say "arXiv" instead.

**Number context.** A number's `comparison` and `condition` (when non-null) must be grounded in its quote. Rules as of the live-run fixes below: a negation or direction word of any length (not, no, without, only, less, more, lower, higher, worse, better, below, above, up, down, before, after and others in `POLARITY_WORDS`) must be in the quote as the same word; every other content word (letters only, four or more of them, not in a small function-word stoplist that includes "versus", "compared", "across") must share a stem with a word of the quote. Failure gives `NumberStatus` "context_not_in_quote" and `applyVerification` drops the number. `unit` is exempt. **Known gaps.**

- Vague quantifiers ("several", "a couple", "both", "single") and ordinals "first"/"second" are allowed. "a pair of" and "a score of" followed by a word are caught; "scores of" is not, since "the scores of both models" is ordinary.
- A single capitalized word at the start of a sentence, or anywhere except after by/from/with, is not checked ("Smith proved it"). A lowercase name is not a name here.

## Piece 4 live-run fixes (2026-11-26)

The first full run (issue #17, PR #18, paper 2611.33402) verified its record but the script failed with the code "malformed", so the PR stayed open. Cause: the record had a number "$30" (unit USD), `spokenValue` had no form for a dollar sign, and when the scriptwriter put `{{n10}}` in narration, `assembleScript` threw a `RenderError` that `checkScriptOutput` reported as "malformed". The repair round got the raw error, not a fix it could act on.

- `spokenValue` says dollar amounts: "$30" is "thirty dollars", "$1" "one dollar", "$1.2B-$2B" "one point two billion to two billion dollars", "-$5" "minus five dollars". A "$" only on the second side of a range, or a dollar amount with "%" or "x", stays unspeakable. Other currencies are still unspeakable (shown on screen only).
- The scriptwriter's brief (`scriptBrief`, now a step) gives each number `spoken`: the exact words the narrator will say, or null. Its instructions say a null `spoken` means on_screen only.
- `checkScriptOutput` turns a `RenderError` into its own code (`number_not_speakable`, `unknown_number_id`) and one repair line per bad placeholder, by beat, rendering each placeholder alone so a template with two bad ids reports both. An id is echoed only when it looks like an id (`[A-Za-z0-9_-]{1,20}`), since it is model text that lands in the public verification.json. Any other assembly error is reported by shape (`errorShape`), not by message.
- `verification.json` now carries `script: { passed, codes, problems }`, and the PR body names the codes when the script fails, so a failed night can be diagnosed from the PR.

Two findings from the security plugin, fixed in the same change:
- The multiplier list missed quadruple, quintuple and sextuple (each with -d, -s, -ing) and the fixed-size group words duo, trio, quartet, quintet, sextet and octet (and plurals). Added; "quartet" left the fuzzy allowlist. "pair of" is rejected with any word before it, a hyphen between, or a placeholder after it ("a pair of {{n}} runs" says two); "a score of" followed by a word is rejected, while "a score of {{n}}" and "the score of the model" pass. "pairs" and "each pair is scored" pass.
- The context rule ignored words under four letters ("not", "no", "low", "up") and matched on a five-letter prefix, so "increase" passed on "increment". Now negation and direction words must appear in the quote as the same word (the rule checks presence, not position), and other words match on a stem (one common suffix removed; equal, or sharing all but the last letter of the shorter stem and at least five letters). A stem under five letters is too short to trust ("normal" and "norm" both stem to "norm"), so those words must be equal or differ by a plural "s" or "es"; the review of PR #19 found that gap. "-ment" is not a suffix here, because "increment" would stem to "incre". Re-verifying the PR #18 record against its page under the new rule kept all 16 numbers.
